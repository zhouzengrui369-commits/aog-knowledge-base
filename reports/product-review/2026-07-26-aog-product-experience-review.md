## §2 阶段 B：产品理念对照

### §2.1 项目声称的能力 vs 用户实际感受到的

| 维度 | 项目声称 | 用户实际感受到 |
|------|---------|---------------|
| 服务谁 | 航空公司维修 + 航材供应链数智化 | 看起来是航空业（但**无证据证明真实用户**） |
| 解决什么 | AOG 时效性 + 信息可信度 + 业务可行动 | 看不出"专业工具感"，更像产品 Demo |
| 数据规模 | 220 城市 / 18 份经验 / 8686 知识片段 | 实际 API = 223 城市 / 10 经验 (文件系统 18) / chroma 8686 索引但 **RAG broken** |
| AI 能力 | RAG 问答 + 每条回答附引用 | 后端 LLM 模式 = MOCK；引用是 sqlite 凑数；引用大多 404 |
| 生产可达 | CloudBase 部署 SOP 就绪 | **公网 SCF 返回 400，集成路径 broken** |
| 数据来源 | 真实 docx 抽取 | 抽取质量差：5 城市共用同一套备件模板；contact 5 家重复；logistics 字段错乱 |

### §2.2 项目内部 baseline 与当前 main 分支的偏差

- **评审版本**: `7d9ac13` (V14, 2026-07-22, main HEAD)
- **内部改进分支**: `integration/sprint-abc` HEAD `7a53723` (V28b, 2026-07-24)

### §2.3 KnowMe 生态价值评估

AOG 项目在 KnowMe 生态中的目标：验证知识能力如何进入真实垂直行业。从评审看：
- ✅ 知识抽取 pipeline (T3 build_index) 工作，技术架构跑通

**KnowMe 生态结论**：AOG **技术架构 demo 已通**，但作为"行业产品模板"对外发布 **不达标**。KnowMe 引用此案例需声明 "pre-production reference architecture"。

  "answer": "⚠️ Mock 模式 · 已根据您的问题在 AOG 知识库中检索相关文档, 答案详见下方'参考资料'区列出的命中文档。\n\n如需更精准回答, 请在 .env 配置 MINIMAX_API_KEY 后重启。",

## §5 P0-P3 问题清单

### P0 致命 (产品不可用)

1. **公网 API base 拼接 bug**: `lib/api.ts:16` `BASE = process.env.NEXT_PUBLIC_API_BASE || "http://localhost:8000"`，build 时被 hardcode 进 chunk (`out/_next/static/chunks/80-*.js`)。当 `BASE = "https://x.tcloudbase.com/api"`（已设置过），`fetch(BASE + "/api/cities")` → `...tcloudbase.com/api/api/cities` → 400 Bad Request。**所有动态数据功能 (首页推荐/城市列表/AI chat/sync status) 在公网全部 broken**。
2. **RAG 检索完全 broken**: 后端 `chroma_client.py` 报 `Collection expecting embedding with dimension of 1024, got 384` — 索引维度 (1024) ≠ 查询维度 (384)。**所有 AI chat 引用是 sqlite fallback 凑数**。重建索引要 ollama 服务，ollama 持续 timeout。
3. **AI chat = Mock 模式**: 无 `MINIMAX_API_KEY` → LLM fallback 到 `MockLLM`，永远返 99 字符 + "请在 .env 配置 MINIMAX_API_KEY 后重启" + 5 个无关引用。
4. **数据新鲜度 = 单次 batch**: 所有 223 城市 `updated_at = 2026-07-17 02:38:5X` (3 秒窗口) — 一次性 build，无业务持续更新机制。
5. **多版本 commit 分散 + 公网部署过时**: main HEAD `7d9ac13` (7/22) 落后 `integration/sprint-abc` HEAD `7a53723` (7/24) 16 个 commit，含 V15-V28b 16 项修复 (Sprint A 认证 / B 地图 / C 航司)。**公网 SCF 仍跑 7/17 老版本，main 落后 5 天**。
6. **SyncService 后台持续抛错**: 每 5 分钟 `sync poll reindex failed: rc=1 err=read_status` + `ollama embed failed at index 2: timed out` — 后台日志污染。

### P1 严重 (数据可信度)

7. **所有城市共用同一套备件模板**: 现行 155 城市里 `parts` 集合只有 38 种 unique templates — 关键件 (3-1531-3 前轮 / C20195162 A320主轮 / C20500100 A321主轮 / C20598000 B787前轮 / C20649000 B787主轮 / 滑油 / 液压油) 在 200+ 城市重复。**不是各城市真实库存，是模板灌入**。
8. **所有城市 contact org 都是东航/国航/南航/海航/空客 5 家**: 这是"全国中介联系表"，**不是各城市本地维修资源**。B-北京大兴和 H-哈尔滨看到的联系人 99% 相同。
9. **84/155 现行城市 stock 全 0**: 真实业务里"所有件都没库存"是不可能的 — 说明 stock 字段是"是否有这个件的标准"而不是"实时库存"。
10. **数据抽取 bug 未修**: `warehouse.main` 数组 4 次重复同一句话 (北京大兴库房描述)；`logistics.rail = "海运: N/A"`, `air = "查询AOG助手"` — 字段语义错乱。
11. **重要枢纽缺失**: 上海浦东 / 上海虹桥 (吉祥主基地) / 北京首都 (PEK, 暂停) — 真实的吉祥员工打开产品找不到自己的主基地。
12. **公网死链**: hero HOT_TAGS 包含 `/city/S-上海浦东` 但 SSG 漏了这个城市，404。
13. **Mock fallback 没有 UI 标注**: 公网用户看到的所有"业务数据"实际是 hardcoded `MOCK_CITIES` (30 个城市)，**但页面无任何 "这是演示数据" 提示** — 直接违反评审规则 §8。
14. **AI references score 全 0.70/0.80** (sqlite fallback 默认值) — 看起来像正常 RAG 排序，实际是 mock。
15. **exposed 个人手机号**: 库房联系人"李伟男 13910301946" / "徐涛 189-3090-6700" / "石培 SPE@satair.com" — **生产环境前必须确认授权**。

### P2 中等 (产品体验)

16. **首页 18 份实战经验" 是 hardcoded**: 实际 API 返 10 经验 (filesystem 18 docx) — 数字不一致。
17. **experiences 列表 18 个 card 链接，但 API 只 10 个**: 8 个死链。
18. **`exp-001.html` / `exp-002.html` SSG 静态页存在，但后端无对应 id**: 静态页 client fetch 404，loading 永驻。
19. **"最后更新" 显示 2026-04-15** (mock fallback 用旧值)，与 API 实际 2026-07-17 不一致。
20. **404 错误页是 Python http.server 默认错误页**，不是产品设计的"城市未找到"友好提示。
21. **Search dropdown 4 个 query 都返 6 个相同结果**: search 看起来工作但智能度低。
22. **备用 mock 数据的 SUMMARY 字段很多是空** (`content_md=0` 列表) — list endpoint 故意不返 content (避 SCF 6MB) 是设计决定，但 UI 没"详情见详情页"引导。

## §7 最重要的 3 项整改（按 ROI 排序）

### 整改 1 · API base 拼接 + RAG 维度修复 (1 天可治本)
- **修 `lib/api.ts:16`**: 改 `BASE = process.env.NEXT_PUBLIC_API_BASE?.replace(/\/api$/, "") || "http://localhost:8000"` (去尾 /api)
- **修 RAG 维度**: `chroma_client.py` 用 sentence-transformers/all-MiniLM-L6-v2 (384 维) 重建索引 (替换 1024 维 ollama embed)
- **修 LLM mock**: 在 `.env.cloudbase.example` 文档 + 启动脚本里加 `MINIMAX_API_KEY=$NJX_PROD_KEY` (硬编码从 NJX 主控台拉)
- **效果**: 公网 API 全部 200；AI chat 至少返真实 LLM 答案；RAG 检索出真相关文档

### 整改 2 · 数据抽取质量 + UI 标注 (1 周)
- **数据层**: 重写 `pipeline/extract_city.py` — 真正按城市 docx 抽取各自备件/联系人/库房，而不是套模板
- **抽取后**: 跑 1 轮 LLM judge: "B-北京大兴 联系人应该有北京本地维修单位" — 把"全国中介表"筛掉
- **UI 标注**: 在城市详情页底部加显眼 banner: "本数据来源于 {source_path}，最后更新 {date}，仅供参考"
- **mock fallback**: 加 "演示数据" 红框提示当数据从 MOCK_CITIES 来时
- **效果**: 同一模板套 200 城市问题解决；用户能区分真实 vs 演示

### 整改 3 · 同步 + 主基地覆盖 (3 天)
- **主基地补齐**: 手工补 docx 录入 "上海浦东" / "上海虹桥" / 更新 "北京首都" 状态为"现行" (如果业务实际现行)
- **SyncService 重写**: 改为 webhook 触发 (而不是 5min poll)，失败重试 3 次后告警
- **ollama 替换**: 改 sentence-transformers 本地计算 (不依赖 ollama 服务)
- **效果**: 吉祥主基地不掉链；后台日志干净；数据可业务持续更新
