## 根因

1. SQLite `experiences` 表没有内容发布标记，列表接口对空 `content_md` 与 `Sheet1` 记录一视同仁。
2. 详情服务端页面只读取兼容字段 `exp.content`，真实 API 返回的 `content_md` 未被解析，导致有正文时也可能显示空白。
3. 页面源码直接渲染内部构建说明，生产用户可见。

## 修复行为

- 首次读取旧数据库时幂等增加：

```sql
ALTER TABLE experiences
ADD COLUMN has_content INTEGER NOT NULL DEFAULT 0;
```

- 以非空正文而不是标题或 summary 判定 `has_content`；空字符串、标题-only、`Sheet1` 等记录标记为 0。
- `/api/experiences` 在分页前过滤 `has_content=0`，避免空记录占用默认 3 条配额。
- `/api/experience/{id}` 对未发布空壳返回 404 `experience not published`。
- 前端从 `content_md` 构建章节并交给 `ExperienceContentView` 渲染。
- 开发诊断只在 `NEXT_PUBLIC_DEBUG=true` 时出现。
