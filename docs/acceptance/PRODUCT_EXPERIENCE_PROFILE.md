# AOG AI 知识库 · 项目体验档案

> 本文件基于 `PRODUCT_EXPERIENCE_REVIEWER_CORE v1.0.0` 编写，定义 AOG AI 知识库项目的产品体验承诺、目标用户、专项用户旅程、专项评分、专项阻塞条件、Owner Human Gate 与报告命名。
>
> 本文件**只定义项目体验档**，不复制 Core 章程内容；如需了解评审方法、证据纪律、裁决结构与复验流程，请阅读 `PRODUCT_EXPERIENCE_REVIEWER_CORE.md`。

## B. 项目体验档案

### 1. 核心产品承诺

AOG 应让航空维修、航材供应链或运行保障用户感受到：

> 这是一个理解 AOG 场景、能够快速提供可信依据和下一步行动的专业行业工具，而不是资料网站或展示性 Demo。

核心价值链：

```
快速定位业务对象
→ 获取结构化行业信息
→ 判断数据来源与新鲜度
→ 形成可执行的处置路径
→ 在错误和高压力条件下保持可靠
```

### 2. 目标用户视角

Blind User Reviewer 应扮演：

> 一位正在处理飞机停场事件、需要在有限时间内查找当地维修资源、联系人、航材和物流支持的值班人员。

使用合成或授权场景，不得擅自暴露真实敏感业务数据。

### 3. 项目专项用户旅程

#### A1：首页和行业定位

- 进入真实网站或候选；
- 不阅读外部说明；
- 判断产品服务谁、解决什么问题；
- 检查核心行动入口；
- 判断是否体现 AOG 的时效性和业务压力。

#### A2：定位城市、机场或保障站点

至少测试：

- 推荐入口；
- 搜索；
- 字母导航；
- 地图导航；
- 中文城市名；
- 大小写或 URL 编码；
- 数据不完整或暂停城市；
- 移动端窄屏。

判断：

- 是否能快速到达目标；
- 城市、机场和站点关系是否清楚；
- 导航是否稳定。

#### A3：获取结构化业务信息

查看当前支持的：

- 机场；
- 机队；
- 联系人；
- 航材；
- 仓库；
- 物流；
- 维修和保障资源；
- 其他专业信息。

判断：

- 信息是否结构化；
- 哪些是真实、模拟、缺失或未知；
- 电话、邮箱和地址是否可用；
- 数据来源和更新时间是否可见。

#### A4：限时完成一个 AOG 任务

设计一个明确任务，例如：

> 某架飞机在目标机场发生 AOG，需要在十分钟内找到联系人、可能的备件支持和运输方案。

记录：

- 用时；
- 点击路径；
- 获得的信息；
- 缺失信息；
- 下一步行动；
- 是否需要离开产品大量补查。

#### A5：AI 行业问答

提出至少三类问题：

1. 可由产品数据直接回答；
2. 需要综合多个来源；
3. 当前没有可靠依据。

判断：

- 是否引用来源；
- 是否区分事实、推断和建议；
- 无依据时是否拒绝编造；
- 行业术语是否准确；
- 是否提供可执行结果。

#### A6：数据可信度和新鲜度

检查：

- 数据来源；
- 更新时间；
- 数据所有者；
- 公开、受控和未知数据的区分；
- Mock / Fixture 标识；
- 数据冲突；
- 过期与替代。

> 页面功能正常但数据不可验证时，不得视为可交付。

#### A7：异常、性能和恢复

至少测试：

- 不存在的城市；
- 空字段；
- API 超时；
- backend 不可用；
- 客户端字段类型异常；
- URL 编码异常；
- 慢网络；
- 移动端；
- 大量数据。

判断：

- 是否崩溃或空白；
- 是否虚假成功；
- 用户是否知道如何继续；
- 核心任务是否在压力下仍可完成。

#### A8：敏感信息和现实风险

检查：

- 联系人；
- 航材；
- 仓库；
- 运行保障信息；
- 任何可能不适合公开的数据。

判断：

- 是否区分权限；
- 是否暴露敏感信息；
- 错误信息是否可能造成现实损失；
- 是否提供适当风险提示。

### 4. 项目专项评分

每项 1–5 分，N/A 不计入：

1. 首次行业定位理解；
2. 行业专业感；
3. 高压力场景效率；
4. 导航和信息架构；
5. 数据可信度；
6. 来源与更新时间透明度；
7. 信息到行动的转化；
8. AI 回答的行业可信度；
9. 异常状态可靠性；
10. 敏感信息与风险控制；
11. 生产产品感；
12. 作为行业产品模板的复用价值；
13. 预测持续使用阻力。

### 5. AOG 专项阻塞条件

以下任一成立，通常不得判 `EXPERIENCE_READY`：

- 页面可用但关键数据来源未知；
- 关键数据明显过期却没有提示；
- AI 在无依据时编造行业事实；
- 敏感联系人或业务数据被不当公开；
- 用户无法在目标时间内完成核心 AOG 任务；
- 错误信息可能导致现实业务损失；
- Mock 或 Fixture 被呈现为生产数据；
- API 成功但界面展示错误或不可行动。

项目专项阻塞状态：

- `BLOCKED_DATA_TRUST`
- `BLOCKED_SENSITIVE_DATA_EXPOSURE`
- `BLOCKED_OPERATIONAL_RISK`

### 6. AOG Human Owner Gate

所有 P0 关闭后，生成十分钟人工脚本：

1. Owner 选择一个熟悉的城市或机场；
2. 在十分钟内完成一个合成 AOG 任务；
3. 找到联系人、保障资源、航材或物流信息；
4. 核对至少一个数据来源和更新时间；
5. 提一个无可靠依据的问题；
6. 检查 AI 是否诚实拒绝或限定；
7. Owner 回答：
   > 我是否愿意在真实业务中把这个产品作为处置依据的一部分？

AI 只能输出 `HUMAN_OWNER_GATE_REQUIRED`。

## C. 本轮启动指令

首次安装完成后：

1. 读取 Core 和 Profile；
2. 必须访问真实产品；
3. 使用合成但业务合理的 AOG 场景；
4. 将页面功能、数据可信度和现实风险分开裁决；
5. 判断评审模式；
6. 优先使用隔离 Blind User Reviewer；
7. 不修改代码、数据或部署配置。
